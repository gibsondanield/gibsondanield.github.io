What's wrong with the Venn diagram

The usual join cheat sheet draws two overlapping circles, A and B, and shades parts of them: the overlap for INNER JOIN, all of A for LEFT JOIN, and so on. It's memorable, but it treats a join as a set operation on rows, and it isn't one. Set operations are UNION, INTERSECT and EXCEPT; they take rows of the same shape and return rows of that shape. A join returns new, wider rows, each built from a row of A and a row of B. The circles can't show three things that matter:

  • The columns. Every output row has A's columns and B's columns.
  • The NULLs. When an outer join keeps a row that matched nothing, the other table's columns are filled with NULL.
  • The row count. A key that appears twice in B makes its partner in A appear twice in the output. The "overlap" can be bigger than either circle.

So here's the alternative: draw the result table itself.

Two small tables

CREATE TABLE A (key INT, a TEXT);
INSERT INTO A VALUES (1,'a1'), (2,'a2'), (3,'a3');
CREATE TABLE B (key INT, b TEXT);
INSERT INTO B VALUES (2,'b1'), (3,'b2'), (3,'b3'), (4,'b4');

One picture for every join

Below is the result of A FULL JOIN B ON A.key = B.key, the join that keeps everything. Its rows fall into three bands: rows of A that matched nothing, matched pairs, and rows of B that matched nothing. Every other join is just a choice of which bands to keep. The bars on the right show the choices, with the number of rows each one returns.

matchedA INNER JOIN B ON A.key = B.key3

B onlyA RIGHT JOIN B ON A.key = B.key WHERE A.key IS NULL1
unmatchedA FULL JOIN B ON A.key = B.key WHERE A.key IS NULL OR B.key IS NULL2

Plain JOIN means INNER JOIN, and LEFT JOIN is short for LEFT OUTER JOIN. RIGHT JOIN is the same as a LEFT JOIN with the tables swapped, so many people never use it.

What the picture makes obvious

Joins can multiply rows

A has three rows, but A LEFT JOIN B returns four, because a3 matches two rows of B and comes out once per match. This is the classic way a join quietly inflates a total: SUM over a column of A after joining to B counts a3 twice. If you only want to know whether a match exists, use a semi-join, which returns each row of A at most once:

SELECT * FROM A
WHERE EXISTS (SELECT 1 FROM B WHERE B.key = A.key);   -- a2, a3: 2 rows, not 3

Test for NULL with IS NULL, never = NULL

The "A only" band is the rows where B's columns are NULL. But B.key = NULL is never true. Comparing anything with NULL, even NULL itself, gives unknown, and WHERE drops unknown rows, so WHERE B.key = NULL returns nothing at all. The 2017 version of this sheet made exactly that mistake. It has to be IS NULL.

Test the join key (or another column declared NOT NULL), not any column of B. A matched row can have a NULL in an ordinary column of B, which would make it look unmatched. The join key can't be NULL in a matched row, because NULL never equals anything.

A WHERE on the right table undoes a LEFT JOIN

In the "A only" band, every B column is NULL. So any WHERE condition on a B column, like WHERE B.b <> 'b3', is unknown there, and the band disappears: the LEFT JOIN silently becomes an INNER JOIN. To filter B but keep unmatched A rows, put the condition in the ON clause:

SELECT * FROM A LEFT JOIN B ON A.key = B.key WHERE B.b <> 'b3';  -- 2 rows, a1 is gone
SELECT * FROM A LEFT JOIN B ON A.key = B.key AND B.b <> 'b3';  -- 3 rows, a1 kept

NULL keys never match

A row of A with key NULL always lands in the "A only" band, even if B also has a NULL key. Joining on nullable columns is fine, as long as you expect those rows to fall out of an inner join.

Things the picture doesn't cover

  • Anti-joins with NOT IN. WHERE A.key NOT IN (SELECT key FROM B) looks like the "A only" query, but if B has even one NULL key it returns nothing, for the same reason = NULL does. NOT EXISTS doesn't have this problem, and neither does the LEFT JOIN … IS NULL form above.
  • CROSS JOIN pairs every row of A with every row of B: 3 × 4 = 12 rows, no bands at all. An inner join is a cross join filtered by the ON condition.
  • USING and NATURAL JOIN merge the two key columns into one. In a full join, the merged key is COALESCE(A.key, B.key), so it's never NULL even in the unmatched bands.
